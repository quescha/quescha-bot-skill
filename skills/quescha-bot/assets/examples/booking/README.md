# Пример: запись в салон

Синтетический пример без клиентских данных и реальных интеграций. В нём есть две таблицы, ввод имени, телефона и даты, получение цены из справочника, запись заявки, просмотр только своих записей, JS-действие и ветки для пустого результата.

`external.code.js` — исходник сценариев. При каждом `check`, `test`, `mutate` и `build` CLI компилирует его и обновляет действия в памяти; редактировать скомпилированные строки `external[].actions` вручную не нужно.

Скопируйте папку в отдельную рабочую директорию и выполните:

```bash
node "$QB" check booking
node "$QB" test booking
node "$QB" mutate booking
node "$QB" build booking
node "$QB" inspect booking/dist/booking-demo.zip
```

Локальный dry-run исполняет JS-действие с тестовыми данными из `dryrun.js`, но не запускает серверный runtime Quescha. После импорта проверьте полный диалог двумя разными подписчиками: второй не должен увидеть записи первого.
